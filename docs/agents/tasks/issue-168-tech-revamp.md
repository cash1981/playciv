# Tech revamp: card art and a level-browsable picker

- **Slug:** `issue-168-tech-revamp`
- **Branch:** `feat/issue-168-tech-revamp`
- **Owner:** orchestrator (Claude, Opus 5.5)
- **Status:** ready for the coder

## Goal

[Issue #168](https://github.com/cash1981/playciv/issues/168) has two parts:

1. The tech pyramid (`TechTree.tsx`) shows the real tech card art for a researched slot,
   instead of just the name. Level 5 (Space Flight) can now show its card too.
2. Choosing which tech to research is no longer a `<select>` combo box. It is a set of tabs, one
   per level (1-5), each showing that level's available techs as cards. Clicking a card opens a
   detail view with the full card image and its rules text, with a "Research" button. This must
   stay screen-reader usable: every card carries real text (name, level, and — for levels 1-4 —
   the tech's effect), not just an image.

## Why

Quoting the issue: "Instead of having the boring tech tree with text only I want to build it
using real tech card images" and "I want users to be able to see the techs cards they want to
research and read what they do and see the cards... instead of the combo box we have today."

## Scope

**In:**

- Card art in the pyramid (part 1) and in the new picker (part 2).
- Replacing the `<select>` combo box entirely with level tabs + a card grid + a detail dialog.
- A `tools/tech-assets.ps1` generator that copies the already-cropped card photos
  (`Civilization/Moderator/techs/*.jpg`, gitignored, prepared in a separate session) into
  `packages/web/public/items/`, named so `itemImage()` resolves them.
- Effect text for levels 1-4, transcribed by the orchestrator into `techText.ts` (see below) —
  do not re-transcribe or edit this file's content, only wire it in.

**Out:**

- Per-tech mechanical effects are **not** implemented or enforced by the engine. They are display
  text only, exactly like `SocialPolicyPanel`'s reference dialog already says for social
  policies ("Card text is shown for reference only; the engine records the chosen policy but does
  not enforce its effects."). Reuse that same sentence's spirit for techs.
- No change to `TechItem`, `chooseTech`, `availableTechs` or any engine reducer. This is a
  read-only, presentation-layer feature.
- Do not touch `old-civ-rest`, `Civilization/Moderator/gamedata-faf-waw.xlsx`, or
  `packages/engine/data/gamedata-faf-waw.json`. The tech "Description" column in that spreadsheet
  was never filled in for any tech (confirmed: every `Level N Tech` sheet row has only a `Name`
  cell) — that is why `TechItem.description` is `null` for every tech today, and why the
  transcription is a separate client-side file instead of routed through `item.description`
  the way `SocialPolicyItem.description` is. **Do not add a description column to the
  spreadsheet or the generated JSON.** That file is autogenerated
  (`Rediger ikke manuelt` / "do not edit manually") and editing the source-of-truth spreadsheet
  to add content that was never there misrepresents the reference material.
- Space Flight has no effect text (see `techText.ts`'s own comment) — leave it with just its
  name and image, same as the old client always showed it.

## Reference

- Old system: `old-civ-web/app/views/partials/techtree.html` and `TechController` (already cited
  in `TechTree.tsx`'s own file comment) for the pyramid; the current `<select>` in `TechPanel.tsx`
  for the picker. Neither had card art or per-tech text — this is genuinely new UI, not a port of
  an old screen, which is why the closest existing precedent to copy is `SocialPolicyPanel.tsx`
  (issue #140), which already solved "cards you may pick, plus a `?` reference dialog with card
  text" for a sibling feature.
- Rules text source: `packages/web/public/help/Civ_Tech_FF-WW.-2.jpg`, already shipped by the old
  client and still in the repo. It is the closest thing to an official tech reference sheet.
  Already transcribed into `techText.ts` — read that file's header comment for the full
  provenance note, and spot check a handful of entries against the image before relying on it.

## Approach

### 1. `packages/engine/src/item.ts` — one-line change

`itemImage()`'s `tech` case currently shares a switch arm with `hut`/`village` and appends the
shared `PNG` constant (`.png`). The prepared card photos are `.jpg`. Split `tech` into its own
case using `.jpg` directly, rather than converting 45 images to PNG or touching the shared `PNG`
constant used by every other item kind:

```ts
case 'hut':
case 'village':
  return `${item.name}${PNG}`.replace(/ /g, '')
case 'tech':
  return `${item.name}.jpg`.replace(/ /g, '')
```

Keep everything else in the function unchanged. Update `ItemCard.tsx`'s file comment if it still
claims every item has no exceptions to the PNG convention — check before assuming it needs a
change.

### 2. `tools/tech-assets.ps1` — new script, modeled on `tools/item-assets.ps1`

Same shape as `item-assets.ps1`: a `param()` block for the source and destination directories
(default source `Civilization/Moderator/techs`, default destination
`packages/web/public/items`), a directory existence check, then a copy loop. Unlike
`item-assets.ps1`, **this one renames while copying** — the source file names
(`metalworking_lvl1.jpg`) don't match what `itemImage()` asks for (`Metalworking.jpg`). Use an
explicit ordered map from destination name to source name (same pattern as `item-assets.ps1`'s
`$policyFiles`/`$aliases` tables), not a derived/parsed transformation of the snake_case name —
several techs don't transform mechanically (`Metal Casting` → `metal_casting`, but
`Metalworking` → `metalworking` with no underscore; `Replacement Parts` → `replaceable_parts`,
a genuine name mismatch between the spreadsheet and the physical card, same situation
`item-assets.ps1` already handles with its `ReplaceableParts.png = ReplacementParts.png` alias).

The full map (destination filename = source filename), verified against
`packages/engine/data/gamedata-faf-waw.json`'s `Level 1-4 Tech` sheets and
`packages/web/src/lib` `Space Flight` name in `gamedata.ts`:

### 3. `packages/web/src/views/TechTree.tsx` — card art in the pyramid

Every `researched` slot currently renders as a `<div className="tech-slot researched">` with the
name as text. Give it the card image, same convention `ItemCard.tsx` uses
(`/items/${encodeURIComponent(fileName)}`, where `fileName` is `${name.replace(/ /g, '')}.jpg`
per the item.ts change above — but `TechTree.tsx` intentionally does not import the engine `Item`
type, per its own file comment ("lays out whatever list of techs it is given"), so don't import
`itemImage()` here; compute the same file name inline or export a small shared helper if that
reads better). Keep the `title` attribute (or move the name to `alt`) so the tech name is still
readable/accessible when the image fails or for a screen reader — same `onError` fallback pattern
`ItemCard.tsx` uses (hide the broken image, let the text underneath show). The empty/unresearched
slots (trade cost) are unchanged — there is no "back of a tech card" art available.

Existing tests: `TechTree.test.tsx` — check it and update/add cases for the new image, without
weakening the existing ones (slot counts, level ordering, hidden marker).

### 4. `packages/web/src/views/TechPanel.tsx` — the level-tabbed picker

Replace the `<select aria-label="Choose a tech">` + "Research" button block with:

- A `Tabs` control (`./Tabs.js`, the simple pill tabs already used by `GameList`/`HighscoreView`)
  for levels 1-5, filtering `available` (the `TechItem[]` from `api.availableTechs`) to the active
  level. This is a different tab set from the existing `PlayerTabs` lower in the panel (which
  picks whose pyramid to view) — they serve different purposes and both stay.
- Under the active level tab, a card grid (`<ul className="card-grid">`, the class
  `SocialPolicyPanel.tsx` already uses) of `ItemCard`s for that level's available techs, each
  wrapped to be clickable (role="button" or a real `<button>` per-card, matching how `ItemCard`'s
  existing `onClick`/`onKeyDown`/`role`/`tabIndex` props are used elsewhere — grep for an existing
  clickable `ItemCard` usage, e.g. in the hand/arena views, and follow that exact pattern rather
  than inventing new keyboard handling).
- Clicking a card opens a detail view for that one tech: reuse `ReferenceDialog` +
  `ReferenceCard` (`SocialPolicyPanel.tsx`'s "Show social policy card reference" button is the
  closest existing example, including the `role="dialog"`, `aria-modal`, focus trap and
  `returnFocusTo` behavior `ReferenceDialog` already provides). The dialog shows: the tech's name,
  level, its card image, `TECH_TEXT[tech.name]` from the new `techText.ts` if present (Space
  Flight and any other tech with no entry just don't get that paragraph — do not fall back to
  `tech.description`, which is always `null`), and a "Research" button that does what the old
  "Research" button did: `api.chooseTech(gameId, tech.name)` via `run(...)`, then closes the
  dialog. Disable "Research" while `busy`, same as the old button was disabled.
- Everything below (the `PlayerTabs` player switcher, the pyramid, the hidden-techs list with
  Reveal/Remove) is unchanged.

Existing tests: `TechPanel.test.tsx` — this will need real rework since the `<select>` interaction
it tests no longer exists. Test the new flow: level tabs filter the available list, clicking a
card opens the dialog with the right content, "Research" calls `api.chooseTech` with the right
tech name and closes the dialog, "Research" is disabled while busy. Don't delete coverage for
behavior that didn't change (loading, error state, the player tabs, hidden techs).

### 5. `packages/web/src/styles.css`

Reuse existing classes (`card-grid`, `card`, `card-art`, `card-caption`, `reference-card-grid`,
`reference-card`, `tab`, `tabs`) wherever they already do what's needed. Only add new rules for
something none of those cover — check before adding, this repo prefers extending an existing
pattern over a parallel one.

## Acceptance criteria

- [ ] `tools/tech-assets.ps1` copies all 45 tech card photos into `packages/web/public/items/`
      under the names `itemImage()` resolves; running it twice is idempotent.
- [ ] The tech pyramid (`TechTree.tsx`) shows the card image for every researched slot at every
      level, including level 5 (Space Flight), with the name still available as `alt`/`title` and
      as a fallback when the image is missing/broken.
- [ ] The `<select>` combo box in `TechPanel.tsx` is gone. Techs are browsed via level tabs (1-5)
      showing that level's available techs as cards.
- [ ] Clicking a tech card opens a dialog with its image, name, level and (for levels 1-4) its
      `techText.ts` entry, with a working "Research" button that chooses that tech and closes the
      dialog; the dialog is keyboard-operable (focus trap, Escape closes, focus returns to the
      card that opened it) via the existing `ReferenceDialog`.
  - [ ] Space Flight's dialog has no effect-text paragraph (no entry in `techText.ts`), and does
        not show `tech.description` instead (it is always `null`).
- [ ] Hidden information: no change to what `availableTechs`/`toPlayerView` return — this is a
      pure rendering change. No new test needed for leakage since no new data crosses the
      server/client boundary, but confirm in the report that nothing was added to a projection.
- [ ] `pnpm -r typecheck && pnpm -r test && pnpm -r build` all pass.
- [ ] Verified in the browser: level tabs switch the visible cards, a card opens the detail
      dialog with real art and text, Research works end to end in a live game, and the pyramid
      shows art for a researched tech at more than one level.
